### 这一版的变化（相对 0.7.3）

#### 问题修复

- **`runtimes` 文件夹越来越大（用户反馈占 17 GB）。** 除了两套必需的运行环境（各约 5 GB），还会留下装完保留的 PyTorch 安装包（每套约 2.4–3 GB）和升级后的旧版本运行环境（只能手动清）；暂停过安装的电脑，下载缓存从此不再自动维护；资源管理器还会把硬链接的同一份文件重复相加。现在：新版本运行环境已登记、检查健康、旧版本没有程序在用时，自动删除旧版本（只删安装时记下的文件）；模型安装成功后立刻维护下载缓存，PyTorch 安装包随之清掉；暂停或中断的安装过了续传保留天数（默认 14 天）也会维护；「应用设置 → 存储与缓存」显示运行环境的实际占用（同一文件只算一次），并注明资源管理器会显示多大、下载缓存最多能释放多少。那里的“自动清理已登记的本地缓存”关掉时，这些都不做。
- **不开 AI 断句时，含数字的视频常在最后一步失败。** 第 9 步“锁定最终字幕时间轴”报“字幕保真检查未通过”，前面全白跑（很多用户反馈）。原因有两个：本地断句会把数字和它的量词切开（`一万｜金币`、`第｜二阶段`），最后核对逐条读数字时就以为数字被改了；`十连` 改写成 `10连` 时，如果这句话还没有逐字时间，每个字都拿到整句的时长，只能切出 5 秒的单字。现在断句避开这些位置，改写后改用逐字时间。字幕文字、数字写法和核对规则都没变。
- **日语视频开 AI 校对后，最后一步报“本地修复的文字与时间单元不一致”。** AI 校对的收尾一步对日语也做了中文数字改写：`一万` 变成 `10000`，表示“足够”的 `十分` 变成 `10分`；改写后重建逐字时间时又没算假名，最后本地重切长句就失败了。现在日语、英语任务这一步不做中文数字改写，和不开 AI 时一样保留识别原文；逐字时间也把假名算进去。关掉「数字规范化」并不能绕开（会碰到上一条），请直接更新到这一版。
- **首页「匹配文稿」失败时不再像“没反应”。** 以前点「开始匹配」过一会儿按钮又变回去，什么都没生成也没有说明（失败说明刚写上就被清空）。现在失败原因一直留在对话框里；本机模型出错只显示最后一句错误；电脑内存或页面文件不够时直接写怎么处理；新增「复制错误详情」，方便发给我们。

#### 新增

- **封面编辑器「边框吸附」。** 底部缩放按钮旁多一个「边框吸附：关闭／开启」开关，默认关闭。开启后拖动单张图片，靠近画布某条边就自动贴齐，并沿那条边显示虚线；按住 Alt 或继续拖远就能照旧越界裁切。文字、多选、锁定图层、缩放手柄、键盘微调和数值输入都和以前一样，一次拖动仍只记一步撤销，虚线不会进导出的图片。由外部贡献者 Ee1ex 提交（[PR #5](https://github.com/NOTBAD314/2ByteASR/pull/5)），本版补上英语、日语、韩语、繁體中文界面的文字。

### 已知限制

- **没有代码签名。** Windows 可能显示“未知发布者”；Mac 没有 Apple 公证。请只从本仓库 Releases 下载并核对 `SHA256SUMS.txt`；不需要、也不应该关闭杀毒软件或系统安全设置。
- **Mac 是实验版**：只在 GitHub 虚拟 Mac 上验证过，实体 Mac 与 8 GB 内存的 Mac 没测；窗口很窄时工作台顶部工具栏会重叠。
- **中文的副词“十分”**（`十分感谢`）在中文任务里仍会被改成 `10分`；修正已在源码里，会在之后的版本发布。

- 长拖音正好拖在一个数字中间、中间停了 5 秒以上时，最后一步仍可能报“字幕保真检查未通过”。
- 封面编辑器右下“等比开关控制缩放 · 滚轮查看”在较窄的窗口里会挤成两行（以前就这样）。
- **不填 Key 时**，工作台里自己点的 AI 功能（「AI 断句」菜单、AI 词库校对、翻译、AI 设计等）仍是原来的“缺少 API 密钥”报错；0.7.3 说明里预告的“先说明再处理”还没有进这一版。

- 4× 播放偶发整个窗口停住的原因仍未找到。
- **第三方许可**：Windows 随附的 gyan FFmpeg 9.0 仍缺构建脚本、可能的补丁与部分链接库的确切版本（gyan 没有公开这些材料）。Mac 的 FFmpeg／mpv 来自固定版本的 Homebrew 官方构建。详见 `licenses/DISTRIBUTION-STATUS.md`。

### What changed (compared with 0.7.3)

#### Fixed

- **The `runtimes` folder kept growing (a user reported 17 GB).** Besides the two runtimes that are needed (about 5 GB each), it kept the PyTorch installers after installing (about 2.4–3 GB per runtime) and old runtime versions after upgrades (which could only be removed by hand); on PCs where an install had been paused, the download cache was never maintained again; and File Explorer counts hard-linked files twice. Now an old runtime version is removed automatically once the new one is registered and healthy and no program is using the old one (only the files recorded at install time are deleted); the download cache, including the PyTorch installers, is maintained right after a model installs successfully; paused or interrupted installs are maintained after the resume-retention days (14 by default); and "Application settings → Storage and cache" shows the runtimes' real use (each file counted once), how big File Explorer will say it is, and how much the download cache can free at most. None of this happens when "Automatically clean registered local cache" is off there.
- **With AI line breaking off, videos containing numbers often failed at the last step.** Step 9, "Lock the final subtitle timeline", reported "subtitle fidelity check failed" and everything before it was wasted (reported by many users). There were two causes: local line breaking split a number from its counter word (`一万｜金币`, `第｜二阶段`), so the final check, which reads the numbers line by line, thought a number had been changed; and when `十连` was rewritten as `10连` in a sentence that had no per-character timing yet, every character got the whole sentence's duration, so only 5-second single-character lines could be cut. Line breaking now avoids those positions and uses per-character timing after a rewrite. Subtitle text, number spelling and the check itself are unchanged.
- **Japanese videos with AI proofreading on failed at the last step with "locally repaired text and time units do not match".** The final step of AI proofreading applied Chinese number rewriting to Japanese too: `一万` became `10000`, and `十分` ("enough") became `10分`; rebuilding per-character timing after that then left out the kana, so re-cutting a long line locally failed. Japanese and English tasks no longer get Chinese number rewriting in that step and keep the recognized text, as they already did with AI off; per-character timing now counts kana as well. Turning off "Number formatting" does not avoid this (you then hit the previous item), so please update to this version.
- **Match script on Home no longer looks like "nothing happened" when it fails.** Before, after "Start matching" the button simply went back after a while, nothing was produced and nothing was explained (the failure message was cleared as soon as it was written). Now the reason stays in the dialog; a local model error shows only its last line; when the PC is short of memory or paging file it says what to do; and a new "Copy Error Details" button makes it easy to send us the full error.

#### New

- **Edge snapping in the cover editor.** Next to the zoom buttons at the bottom there is an "Edge snapping: off/on" switch, off by default. When it is on and you drag a single image near an edge of the canvas, the image snaps flush to it and a dashed line is shown along that edge; hold Alt or keep dragging to go past the edge and crop as before. Text, multiple selection, locked layers, resize handles, keyboard nudging and number input work as before; one drag is still one undo step, and the dashed line never appears in exported images. Contributed by Ee1ex ([PR #5](https://github.com/NOTBAD314/2ByteASR/pull/5)); this release adds the English, Japanese, Korean and Traditional Chinese interface text.

### Updating from an earlier version

- **0.7.3, 0.7.2, 0.7.1**: "Check for updates" at the top right of the main window downloads only the program (about 52 MB). **0.7.0**: about 81 MB (the program and licence materials); **0.6.5**: about 464 MB (also the Python runtime and the renderer). Updates are verified after downloading and replace the old files only after you save your project and agree to quit; if anything fails, the previous version is restored automatically. Settings, glossaries, projects, downloaded models and runtimes are all kept.
- **0.6.0 and earlier**: close 2ByteASR and run the 0.7.4 Setup **to install over the old version. Do not uninstall first.**
- **Mac**: there is no in-app update yet. Quit the old version, open the new DMG and drag the app into "Applications" to replace the old one; settings, models and projects are stored in a user folder outside the app (this replacement step has not been tested on a Mac).

### What was checked before release

The program in this release = the build the developer uses every day + cover edge snapping (plus the version number). The daily build's four changes went through real-window checks before it became the everyday build; this round added cover snapping, install, upgrade, in-app update and the Mac build. Everything was done in isolated test folders; no user projects, glossaries, models or API settings were read or written (the recognition check with AI borrowed the developer's own API key read-only).

### Known limitations

### 変更点（0.7.3 との比較）

#### 修正

- **`runtimes` フォルダーが大きくなり続けた問題（17 GB という報告がありました）。** 必要な 2 つの実行環境（各約 5 GB）のほかに、インストール後も残しておいた PyTorch のインストーラー（実行環境ごとに約 2.4〜3 GB）と、アップグレード後の古いバージョンの実行環境（手動でしか消せませんでした）が残っていました。インストールを一時停止したことのあるパソコンでは、それ以降ダウンロードキャッシュが自動で整理されず、エクスプローラーはハードリンクされた同じファイルを二重に数えていました。今は、新しい実行環境が登録されて正常と確認され、古い方を使っているプログラムがないとき、古いバージョンを自動で削除します（インストール時に記録したファイルだけを削除）。モデルのインストールが成功するとすぐにダウンロードキャッシュを整理し、PyTorch のインストーラーも消えます。一時停止や中断したインストールも、再開の保持日数（既定 14 日）を過ぎれば整理します。「アプリ設定 → ストレージとキャッシュ」には実行環境の実際の使用量（同じファイルは 1 回だけ数える）と、エクスプローラーでの表示サイズ、ダウンロードキャッシュで最大どれだけ空けられるかを表示します。そこで「登録済みのローカルキャッシュを自動削除」をオフにしていると、これらは行いません。
- **AI による区切りをオフにしていると、数字を含む動画が最後の段階で失敗することが多かった問題。** 第 9 段階「最終字幕タイムラインの確定」で「字幕の忠実性チェックに失敗」となり、それまでの処理が無駄になっていました（多くの方から報告がありました）。原因は 2 つです。ローカルの区切りが数字とその助数詞を切り離していた（`一万｜金币`、`第｜二阶段`）ため、行ごとに数字を読む最終チェックが「数字が変えられた」と判断していたこと。そして、まだ文字ごとのタイミングがない文で `十连` が `10连` に書き換えられると、全文字に文全体の長さが割り当てられ、5 秒の 1 文字の行しか作れなかったことです。区切りはこれらの位置を避け、書き換え後は文字ごとのタイミングを使うようになりました。字幕の文字、数字の書き方、チェックの規則は変わりません。
- **日本語の動画で AI 校正をオンにすると、最後の段階で「ローカル修復の文字と時間単位が一致しない」となった問題。** AI 校正の最後の処理が日本語にも中国語の数字の書き換えを行い、`一万` が `10000` に、「十分」（じゅうぶん）が `10分` になっていました。さらに書き換え後に文字ごとのタイミングを作り直すとき仮名が数えられず、長い行をローカルで区切り直す段階で失敗していました。日本語と英語のタスクではこの処理で中国語の数字の書き換えをしなくなり、AI オフのときと同じく認識結果のままになります。文字ごとのタイミングも仮名を数えるようになりました。「数字の正規化」をオフにしても回避できません（1 つ前の問題に当たります）。このバージョンに更新してください。
- **ホームの「原稿を合わせる」が失敗したとき、何も起きていないように見えた問題。** 以前は「照合を開始」を押してしばらくするとボタンが元に戻るだけで、何も作られず説明もありませんでした（失敗の説明が表示された直後に消されていました）。今は失敗の理由がダイアログに残ります。ローカルモデルのエラーは最後の 1 行だけを表示し、メモリやページングファイルが足りないときは対処方法を書きます。「エラーの詳細をコピー」ボタンも追加し、詳細を送っていただきやすくしました。

#### 新機能

- **サムネイル（表紙）エディターの「端へのスナップ」。** 下部のズームボタンの横に「端へのスナップ：オフ／オン」のスイッチを追加しました（既定はオフ）。オンにして画像を 1 枚ドラッグし、キャンバスの端に近づけると端にぴったり合い、その辺に沿って破線が表示されます。Alt を押すか、さらに遠くへドラッグすると、これまでどおり端を越えてトリミングできます。文字、複数選択、ロックしたレイヤー、拡大縮小ハンドル、キーボードでの微調整、数値入力はこれまでどおりです。1 回のドラッグは 1 回の取り消しのままで、破線は書き出した画像には入りません。外部の貢献者 Ee1ex さんによるものです（[PR #5](https://github.com/NOTBAD314/2ByteASR/pull/5)）。このバージョンで英語・日本語・韓国語・繁體中文の表示文字を追加しました。

### 바뀐 점(0.7.3과 비교)

#### 수정

- **`runtimes` 폴더가 계속 커지던 문제(17 GB라는 제보가 있었습니다).** 꼭 필요한 실행 환경 두 개(각 약 5 GB) 외에도 설치 후 남겨 둔 PyTorch 설치 파일(실행 환경마다 약 2.4~3 GB)과 업그레이드 후의 이전 버전 실행 환경(직접 지워야만 했음)이 남았습니다. 설치를 일시 중지한 적이 있는 컴퓨터는 그 뒤로 다운로드 캐시가 자동으로 정리되지 않았고, 파일 탐색기는 하드 링크된 같은 파일을 두 번 셌습니다. 이제 새 실행 환경이 등록되고 정상으로 확인되며 이전 버전을 쓰는 프로그램이 없으면 이전 버전을 자동으로 지웁니다(설치할 때 기록한 파일만 지움). 모델 설치가 성공하면 바로 다운로드 캐시를 정리해 PyTorch 설치 파일도 지워집니다. 일시 중지되거나 중단된 설치도 이어 받기 보관 일수(기본 14일)가 지나면 정리합니다. '앱 설정 → 저장소 및 캐시'에는 실행 환경의 실제 사용량(같은 파일은 한 번만 셈)과 파일 탐색기에 표시될 크기, 다운로드 캐시에서 최대 얼마나 비울 수 있는지가 나옵니다. 거기서 '등록된 로컬 캐시 자동 정리'를 끄면 이 작업은 하지 않습니다.
- **AI 줄 나누기를 끈 상태에서 숫자가 들어간 영상이 마지막 단계에서 자주 실패하던 문제.** 9단계 '최종 자막 타임라인 확정'에서 '자막 충실도 검사 실패'가 나와 그 전까지의 작업이 모두 헛수고가 되었습니다(많은 분이 알려 주셨습니다). 원인은 두 가지였습니다. 로컬 줄 나누기가 숫자와 그 단위 말을 떼어 놓아서(`一万｜金币`, `第｜二阶段`) 줄마다 숫자를 읽는 마지막 검사가 '숫자가 바뀌었다'고 판단했습니다. 또 아직 글자별 타이밍이 없는 문장에서 `十连`이 `10连`으로 바뀌면 모든 글자가 문장 전체 길이를 받아 5초짜리 한 글자 줄만 만들 수 있었습니다. 이제 줄 나누기는 이런 위치를 피하고, 바꿔 쓴 뒤에는 글자별 타이밍을 사용합니다. 자막 글자, 숫자 표기, 검사 규칙은 바뀌지 않았습니다.
- **일본어 영상에서 AI 교정을 켜면 마지막 단계에서 '로컬로 고친 글자와 시간 단위가 맞지 않음'으로 실패하던 문제.** AI 교정의 마지막 처리에서 일본어에도 중국어 숫자 바꿔 쓰기를 해서 `一万`이 `10000`으로, '충분하다'는 뜻의 `十分`이 `10分`으로 바뀌었습니다. 그 뒤 글자별 타이밍을 다시 만들 때 가나를 세지 않아 긴 줄을 로컬로 다시 나누는 단계에서 실패했습니다. 이제 일본어와 영어 작업은 이 처리에서 중국어 숫자 바꿔 쓰기를 하지 않고, AI를 껐을 때처럼 인식 결과를 그대로 둡니다. 글자별 타이밍도 가나를 셉니다. '숫자 표기 통일'을 꺼도 피할 수 없으니(바로 앞의 문제에 걸립니다) 이 버전으로 업데이트해 주세요.
- **홈의 '원고 맞추기'가 실패하면 아무 반응이 없는 것처럼 보이던 문제.** 전에는 '맞추기 시작'을 누르고 잠시 뒤 버튼이 원래대로 돌아갈 뿐 아무것도 만들어지지 않고 설명도 없었습니다(실패 설명이 표시되자마자 지워졌습니다). 이제 실패 이유가 대화 상자에 남습니다. 로컬 모델 오류는 마지막 한 줄만 보여 주고, 메모리나 페이징 파일이 부족하면 어떻게 하면 되는지 적어 줍니다. '오류 상세 정보 복사' 버튼도 추가해 오류 내용을 보내기 쉽게 했습니다.

#### 새 기능

- **표지 편집기의 '가장자리 스냅'.** 아래쪽 확대·축소 버튼 옆에 '가장자리 스냅: 끔/켬' 스위치가 생겼습니다(기본은 끔). 켜고 이미지 한 장을 끌어 캔버스 가장자리에 가까이 가면 가장자리에 딱 맞춰 붙고, 그 변을 따라 점선이 표시됩니다. ### 알려진 제한

- **코드 서명이 없습니다.** Windows에서 '알 수 없는 게시자'가 표시될 수 있고, Mac 앱은 Apple 공증을 받지 않았습니다. 이 저장소의 Releases에서만 내려받고 `SHA256SUMS.txt`로 확인하세요. 백신 프로그램이나 시스템 보안 설정을 끌 필요가 없으며 꺼서도 안 됩니다.
- **Mac 버전은 실험판입니다**: GitHub 가상 Mac에서만 확인했으며 실제 Mac과 메모리 8 GB Mac은 확인하지 않았습니다. 창이 아주 좁으면 자막 스튜디오 위쪽 도구 막대가 겹칩니다.
- **중국어 부사 '十分'**(`十分感谢`)은 중국어 작업에서 아직 `10分`으로 바뀝니다. 수정은 소스에 들어 있으며 이후 버전에서 공개합니다.
- **실행 환경 정리의 대가**: 같은 PyTorch가 필요한 다른 모델을 설치하면 약 2.4 GB를 다시 내려받습니다. 실행 환경 두 개(약 10 GB)는 여전히 C 드라이브에 있으며 위치는 아직 바꿀 수 없습니다.
- 길게 늘인 소리가 숫자 한가운데에 있고 5초 넘게 멈춰 있으면 마지막 단계에서 '자막 충실도 검사 실패'가 날 수 있습니다.
- 표지 편집기 오른쪽 아래의 '等比开关控制缩放 · 滚轮查看'은 조금 좁은 창에서 두 줄로 줄바꿈됩니다(이전부터).
- **API 키가 없을 때** 자막 스튜디오에서 직접 실행하는 AI 기능('AI 줄 나누기' 메뉴, AI 용어집 교정, 번역, AI 디자인 등)은 여전히 'API 키 없음' 오류가 납니다. 0.7.3 설명에서 예고한 '먼저 설명하기' 변경은 아직 이번 버전에 들어 있지 않습니다.
- 영어·일본어·한국어 화면에는 아직 중국어로 보이는 글자가 일부 있습니다.
- 4배속 재생 중 가끔 창 전체가 멈추는 원인은 아직 찾지 못했습니다.
- **타사 라이선스**: Windows 버전에 들어 있는 gyan FFmpeg 9.0은 빌드 스크립트, 적용되었을 수 있는 패치, 일부 링크 라이브러리의 정확한 버전이 아직 없습니다(gyan이 이 자료를 공개하지 않았습니다). Mac의 FFmpeg/mpv는 버전을 고정한 Homebrew 공식 빌드입니다. 자세한 내용은 `licenses/DISTRIBUTION-STATUS.md`를 보세요.
